# FINAL ORBIT／最後的軌道　玩家指南

兩年前，你批准了 Astra Dynamics 的首次入軌示範。火箭起飛後失聯，公司失去投資。現在有一個政府委託讓團隊重返太空。你是任務負責人，Alex 管預算和時程，Elena 提供工程與測試建議，Samuel 帶來委託和合作條件。完整劇情節點見[主線](main-story.md)。

## 每章怎麼玩

1. 讀簡報。找出誰需要成果、要收到什麼，以及何時要收到。
2. 選方案。比較硬體或合作帶來的能力、工期和經費，再安排製造與整合。
3. 選擇要驗證的項目。測試能讓你早點知道哪裡有問題，修正才會改變硬體。定版後修改也可能需要重新整合。
4. 送飛行準備審查（FRR）。檢查目前的證據是否適用於這次要飛的配置。必要條件缺件要補齊，審查允許帶著部分剩餘風險飛行時，簽名和後果會寫入紀錄。
5. 執行或交付。看飛行中實際發生什麼、地面收到多少，以及距離合約門檻有多遠。未發射、未交齊、達成委託和額外交付各有結算。

工作台顯示本任務所處的階段。選型、詳細設計、組裝、整合與審查在操作前完成。操作後進入結算。畫面上的 A–F 是遊戲採用的 NASA 計畫生命週期對照。 [NASA NPR 7120.5F 第 2 章](https://nodis3.gsfc.nasa.gov/displayDir.cfm?Internal_ID=N_PR_7120_005F_&page_name=Chapter2)

## 三份委託

### 第一道曙光 · 立方衛星

洪災通行圖需要在第一次通聯結束前交 2 批可見光影像，海灣排水調查需要交 3 段可用的溫度帶。選完委託後，比較兩種搭載的質量上限、交件週數和通聯容量。加裝副感測器能在部分視線受阻時補上資料，也多了一個必須整合的介面。可安排早測，整合沒過時可返工或撤下加裝的儀器再測。首圈先收健康遙測，再送觀測資料。基本交付後，有通聯槽和拍攝機會才會出現追加目標。

**任務日測試（DITL）**是把飛行操作順序在地面走一遍。這裡核對分離、展開和首次發訊的時間。這一局的門檻用搭載條件與報告上的數字。 [NASA《CubeSat 101》§6.9.1](https://science.nasa.gov/wp-content/uploads/2023/06/nasa_csli_cubesat_101_508.pdf#page=67)

### 再一次入軌 · 火箭示範

選定用來驗證介面的 400 km 軌道，或能取得加款、運載限制也更緊的 550 km 太陽同步軌道。把 70 kg 的測試酬載送到合約指定的軌道，並交付足夠的確認資料。第二期經費削減時，畫面會列出本局剩餘款與方案的工作成本。分析和熱試車能告訴你運載餘裕還剩多少，地面站測試則能讓你了解第一次通聯能不能交齊。

若測到資料鏈問題，Elena 會把當局的測試結果與舊失聯紀錄放在一起看。放行台詞和結算依當局的檢查與簽署，舊事故的原因保持未定。

### 月球委託 · 月面科學

選擇資金合作、技術支援或自行完成，安排酬載、著陸備援、供電和奔月路線。合作方會依條件提出要求，例如政府希望提早交付，或願意付費搭載另一項酬載。加上硬體會佔用質量配額，也可能需要多排一段整合工作。在發射後的七段飛行裡，用手上的資源應對實際發生的狀況。只有抵達月面並傳回可用的科學資料，才算完成基本委託。

## 怎麼看結算

從**當初選的方案 → 測到的結果 → 實際交付**往下看。例如整合測出副感測器的資料讀不到，結算會保留那份報告。若你選擇撤掉副感測器並通過重測，飛行只會使用最後放行的配置。驗證有時只縮小不確定性。分析、測試與審查紀錄所提供的證據，適用於做這項驗證時的設計。 [NASA 系統工程手冊 §5.3](https://www.nasa.gov/reference/5-3-product-verification/)

任務履歷可從大廳或登月結算展開，查看各章的最佳成果與歷次拿到的合作條件。立方衛星結算的「重玩這份委託」會為同一份委託抽出新情境，「換一份委託」會回到委託選擇。入軌和登月的「要不要再玩一次？」會為同一任務抽出新情境。

## 常用名詞

| 詞 | 進遊戲時怎麼用 |
| --- | --- |
| 酬載 | 真正提供資料或執行實驗的設備，例如相機或光譜儀。 |
| 餘裕 | 上限還剩多少可以使用。例如火箭能送的質量扣掉目前要載的質量。 |
| 通聯與下傳 | 通聯是地面站有機會和載具聯絡的時間，下傳是把資料傳回地面。 |
| 定版 | 確定要製造的配置。後續變更會花工期，可能需要重測。 |
| 剩餘風險 | 審查時還可能發生的問題。用測試紀錄和失效後果判斷要修、要測，還是能承擔。 [NASA 技術風險管理](https://www.nasa.gov/reference/6-4-technical-risk-management/) |
| 種子 | 用來重現同一局所遇到的事件與風險條件。 |
